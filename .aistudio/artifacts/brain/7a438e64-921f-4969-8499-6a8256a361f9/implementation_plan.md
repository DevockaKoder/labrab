# Интеграция облачной базы данных Firebase Firestore и авторизации преподавателя

План перехода с временного хранения в оперативной памяти на постоянную облачную базу данных Firebase Firestore с авторизацией преподавателя через Google, обеспечивающей сохранение проверок, сводной ведомости и истории между сессиями и устройствами.

## User Review & Critical Decisions

> [!IMPORTANT]
> На основе ответов в интерактивном опросе зафиксированы следующие ключевые решения:

- **Подтверждённое решение 1 (База данных)**: Использование **Firebase Firestore** на бесплатном тарифе Spark (до 1 ГБ данных, 50 000 чтений и 20 000 записей в день — полностью покрывает потребности преподавателя без каких-либо расходов).
- **Подтверждённое решение 2 (Авторизация)**: Вход преподавателя через **Google Auth (Popup)**. Это обеспечивает безопасный доступ к своим журналам и работам студентов без необходимости запоминать отдельные пароли.
- **Стратегия совместимости**: Сохранение возможности локального предпросмотра при отсутствии входа (с кнопкой быстрой синхронизации в облако после авторизации).

---

## 1. Overview & Core Concept

- **Что делает**: Приложение сохраняет все загруженные студенческие файлы, результаты автопроверки кода (баллы, нерешённые задания, сгенерированные отзывы для студентов, статус архивации и отчёты антиплагиата) в облачной NoSQL базе данных Firestore.
- **Целевая аудитория**: Преподаватель (и ассистенты), ведущие проверку лабораторных работ (ЛР3, ЛР4 и последующих) по группам.
- **Ключевая ценность**:
  - Данные не сбрасываются при перезагрузке страницы или закрытии вкладки.
  - Доступ к сводной ведомости с любого компьютера или планшета под учётной записью преподавателя.
  - Мгновенная синхронизация правок (изменение баллов, отправка в архив, выгрузка Excel/CSV).

## 2. User Experience & Visual Design

- **Ключевые пользовательские сценарии**:
  1. *Первый вход / Шапка*: В верхней панели отображается статус подключения к облаку и кнопка **"Войти через Google"** (или карточка профиля преподавателя с аватаром и кнопкой выхода).
  2. *Индикатор синхронизации*: Рядом со сводной ведомостью выводится статус: зелёный бейдж `"Синхронизировано с облаком"` или индикатор `"Сохранение..."`.
  3. *Загрузка и проверка*: Преподаватель загружает архив или отдельные `.py` файлы (ЛР3 или ЛР4). После автоматического прогона тестов результаты сразу сохраняются в Firestore в фоновом режиме.
  4. *Работа со сводной ведомостью*: Архивирование студента, ручная корректировка баллов или копирование отзыва моментально отражаются в базе данных.
  5. *Фильтрация и история*: Сохранённые работы группируются по номеру лабораторной (ЛР3 / ЛР4) и группам студентов, с возможностью просмотра предыдущих семестров/потоков.

- **Визуальный стиль & интерфейс**:
  - Сохранение фирменного строгого академического стиля (Tailwind CSS, чистые карточки, компактные строки таблицы).
  - Модальное окно или аккуратный баннер авторизации в шапке без блокировки интерфейса.
  - Всплывающие уведомления (toasts) об успешном сохранении и синхронизации.

## 3. Key Product Decisions & Trade-Offs

- **Решение 1: Firebase Firestore вместо локального localStorage/IndexedDB**
  - *Выбор*: Firebase Firestore.
  - *Почему*: Firestore гарантирует переносимость данных между устройствами (дома, на кафедре, в аудитории) и совместную работу, при этом полностью укладывается в пожизненный бесплатный лимит Google Cloud Spark.
- **Решение 2: Вход через Google Popup (`signInWithPopup`)**
  - *Выбор*: Google Provider через всплывающее окно браузера.
  - *Почему*: Встраивание в iframe AI Studio надёжно работает именно со всплывающим окном авторизации (в отличие от `signInWithRedirect`, который может блокироваться политиками межсайтовых переходов).
- **Решение 3: Архитектура коллекций (Scoped per Teacher / Multi-tenant ready)**
  - *Выбор*: Коллекция `submissions` с привязкой к `teacherUid`, `labId` и уникальному ID студента/файла.
  - *Почему*: Защищает данные одного преподавателя от перезаписи, позволяет легко фильтровать работы конкретной лабораторной работы.

## 4. Technical Architecture & Data Strategy

```

│                   Firebase Auth                        │

                            │ (auth state listener)
┌───────────────────────────▼────────────────────────────┐
│                  React Application                     │
│  ┌──────────────────────────────────────────────────┐  │
│  │ FirebaseContext / useAuth (User Profile & Ready) │  │
│  └────────────────────────┬─────────────────────────┘  │
│                           │                            │
│  ┌────────────────────────▼─────────────────────────┐  │
│  │ SubmissionsStore (Live Firestore snapshot sync)  │  │
│  └────────┬─────────────────────────────┬───────────┘  │
└───────────┼─────────────────────────────┼──────────────┘
            │ (run tests & save)          │ (read / update)
┌───────────▼─────────────┐ ┌─────────────▼──────────────┐
│  Code Runner & Parser   │ │   Summary Table & Review   │
│  (Pyodide AST & Tests)  │ │   (Archive, Grade, Export) │

            │                             │
```

### Модели данных и безопасность

1. **`firebase-blueprint.json`**:
   - Строгая схема сущностей `StudentSubmissionEntity` и `PlagiarismReportEntity`.
   - Валидация типов данных, строковых длин и обязательных полей.
2. **`firestore.rules`**:
   - Правила доступа с привязкой к `request.auth.uid`: каждый преподаватель имеет полный доступ на чтение, создание, обновление и архивирование только своих записей.
   - Защита от неавторизованной записи чужих работ.
3. **Обработка ошибок**:
   - Стандартизированный обработчик ошибок доступа `handleFirestoreError` с информативными сообщениями.

## 5. Пошаговый план внедрения

1. **Инициализация Firebase**:
   - Запуск инструмента подключения Firebase Firestore и Auth к проекту.
   - Создание файла `firebase-blueprint.json` и настройка безопасных правил `firestore.rules`.
2. **Подключение SDK в приложение**:
   - Добавление `firebase` SDK и конфигуратора клиента `src/firebase.ts`.
   - Создание `AuthContext` с кнопкой входа через Google в правом верхнем углу интерфейса.
3. **Синхронизация данных**:
   - Подключение хука `useSubmissions` с подпиской в реальном времени (`onSnapshot`) на работы текущей выбранной лабораторной (`labId`).
   - Автоматическое сохранение проверенных файлов сразу после завершения тестирования.
   - Сохранение статуса архивирования и ручных правок оценки в Firestore в один клик.
4. **Тестирование и валидация**:
   - Проверка компиляции, входа под тестовым аккаунтом, сохранения ЛР3 и ЛР4, проверки сохранения между перезагрузками страницы.
